Document Agents approved

Technical spec. React site (port 4000) + FastAPI (port 8000) + Chroma + Gemini.

How this works, in plain language

A React website talks to a Python API. On upload, the API reads the PDF page by page, splits it where the meaning changes, turns each chunk into numbers, and stores them in Chroma. On a question, the 5 closest chunks go to Gemini with a strict rule: answer only from them, otherwise say "not found in this document."

Components

Backend: upload, document, chat, sessions

POST /upload-pdf, GET/DELETE /document, POST /chat, POST/GET /sessions, GET/DELETE /sessions/{id}. A session is read-only when its document id differs from the current document.

Frontend: screens

UploadScreen; Header, Sidebar (collapsible), DocumentCard (hover delete), Chat (three-dots while waiting), ConfirmDialog.

Data model

storage/uploads, storage/chroma, storage/document.json, storage/sessions/session_<time>_<date>.json with visibility, document_id, messages.

Failure modes

What breaks and what the user sees
  • Unusable PDF → "this document is invalid."
  • Gemini fails → short error in the chat.
  • Off-topic question answered anyway → strict prompt + build-time tests; add a score threshold if it leaks.
  • Follow-ups without a rewrite step → tested in the build.
  • Slow semantic chunking → loader; timing measured.
To verify early in the build

Current Gemini model name and limits; package versions install together; chunker speed; logo file; final grounding prompt.

How to run it

Backend: venv, pip install -r requirements.txt, .env with GOOGLE_API_KEY, uvicorn main:app --port 8000. Frontend: npm install, npm run dev. Open http://localhost:4000.
